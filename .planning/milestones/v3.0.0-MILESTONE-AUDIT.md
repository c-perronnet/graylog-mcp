## E2E Flow Viability — BLUE-01 chain

PASS structurally. `src/tools/blueprints/setup-app-monitoring-stack.js`
ships a 6-step chain whose shape matches the BLUE-01 contract:

| Step | Tool | Method | Path | dependsOn |
|------|------|--------|------|-----------|
| 1 | `create_stream` | POST | `/api/streams` | — (root) |
| 2 | `create_pipeline_rule` | POST | `/api/system/pipelines/rule` | — |
| 3 | `create_pipeline` | POST | `/api/system/pipelines/pipeline` | — |
| 4 | `connect_pipelines_to_stream` | POST | `/api/system/pipelines/connections/to_stream` | array: `[step1.response.stream_id → stream_id, step3.response.id → pipeline_ids[0]]` |
| 5 | `create_dashboard` | POST | INTERNAL Search+View 2-step chain | single: `step1.response.stream_id → widgets[].streamIds[0]` (C7 preserved) |
| 6 | `create_event_definition` | POST | `/api/events/definitions?schedule=false` | single: `step1.response.stream_id → config.streams[0]` (M1 preserved) |

Structural verification:

- Step 1 returns `{stream_id: "..."}` (NOT `id`) — the apply walker
  resolves `step1.response.stream_id` per the Phase 3 wire shape.
  Pinned by test "apply substitutes step 1 stream_id" (T-06-05-06).
- Step 5 is a SINGLE blueprint step that emits TWO HTTP round-trips
  (Search POST → View POST). The agent NEVER sees the intermediate
  Search ID. The wrapper substitutes step 5a's response into step 5b's
  `search_id` body field before firing — the C7 mitigation is
  structurally identical to standalone `create_dashboard` inside the
  blueprint composition.
- Step 6 ships `?schedule=false` unconditionally on the wire — M1
  acceptance gate preserved inside the blueprint chain.
- All four `dependsOn` references resolve to wire-shape paths on
  prior-step response payloads. The apply walker uses dotted-path
  substitution; no agent input ever composes into a URL path
  (T-06-05-09).

The chain is structurally sound. Not run live (per audit time-box +
MILESTONE-SUMMARY's "deferred to /gsd-verify-work follow-up" stance);
the live BLUE-01 apply remains in the outstanding-UAT list below as a
deferred verification, not a failure.
