<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → MCP handler | Lifecycle tools accept ONE arg (inputId) — small attack surface. |
| MCP handler → Graylog | Two lifecycle endpoints reached via makeClient.request — auth + writable-gate enforced. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-01 | Elevation of Privilege | Agent starts/stops a critical production input bypassing dry-run | mitigate | mutatingBase enforces dryRun: true by default; agent MUST explicitly pass dryRun: false. Phase 0 schema contract — no new defense needed here. |
| T-01-03-02 | Tampering | Agent attempts start_input against a writable=false connection | mitigate | Defense in depth: defineMutatingHandler refuses with reason: "connection_read_only" BEFORE build runs; src/graylog/client.js refuses non-GET BEFORE axios. The wrapper layer alone catches this; the client layer is the safety net for service-layer bypass. Verified by Test 5 in Task 1. |
| T-01-03-03 | Information Disclosure | start/stop tool returns input config in response (e.g., echoes secrets) | accept | Graylog's InputCreated.create(id) / InputStopped.create(id) responses contain only { id } — no configuration data. No disclosure surface. |
| T-01-03-04 | Denial of Service | Agent rapidly toggles start/stop in a loop | accept | Graylog handles repeated lifecycle calls idempotently (PUT on already-running = no-op; DELETE on already-stopped = no-op). MCP doesn't rate-limit; this is a Graylog-side concern. Out of scope. |
| T-01-03-05 | Repudiation | Agent denies issuing a stop_input that took down production logging | accept | The idempotency key from mutatingBase is emitted in every response (dry-run and apply) — the agent's trace surface lets the operator correlate. Beyond MCP scope. |
</threat_model>
