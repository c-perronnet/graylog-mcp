<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent -> deleteIndices boolean | Inverted default at the wrapper layer: defaultValue false (D-04) is the safety-relevant choice. Even an agent that forgets the param cannot trigger destruction. |
| Build() -> confirmation token | Token is deterministic over PUBLIC state (indexSetId + sorted indexNames + messageCount). No secrets in the hash inputs. |
| Dry-run -> apply binding | Hash recomputed in build() on every call. If indexes change between dry-run and apply (new index opened, messages ingested), the hash mismatches and apply refuses. Stateless, no MCP-side replay window. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | T (tampering) | Agent-replayed confirmationToken across deleteIndices values | mitigate | D-02 locked literal: computeC1Hash REJECTS if deleteIndices !== true. A hash issued for any other input can never validate against a deleteIndices:true call. |
| T-02-03-02 | D (denial of service) | Stats hard-block (D-05) | accept | The block is the safety choice. Elasticsearch unreachable -> dry-run refuses -> agent sees "stats_unreachable" -> agent cannot destroy data without seeing the blast radius. The DoS surface is bounded by the agent's own retry budget. |
| T-02-03-03 | E (elevation) | Confirmation gate vs writable gate ordering | mitigate | Writable gate fires in handler.js step 3 (BEFORE build()); confirmation gate fires in step 7 (AFTER build, BEFORE apply). Read-only connections refuse delete_index_set regardless of args.confirm or deleteIndices. Defense in depth. |
| T-02-03-04 | I (information disclosure) | Index names in dry-run | accept | Index names are public Graylog metadata visible via any list call. Surfacing them in cascades.indices does not leak secrets. |
| T-02-03-05 | R (repudiation) | Async envelope without job_id | mitigate | Graylog's DELETE response is 204 with no body — we cannot extract the system_job_id at apply time. The async envelope says job_id_observable_at: /system/jobs and the tool description tells the agent to grep for IndexSetCleanupJob in the list. The agent's audit trail is the agent's call log + Graylog's @AuditEvent server-side log. |
| T-02-03-06 | I (information disclosure) | confirmationToken in fixtures | accept | The 64-hex token is a content-hash of public state, NOT a secret. Plan 05 extends `test/auth-redaction.test.js`'s allowlist to recognize `confirmationToken` context (mirroring the existing `idempotencyKey` allowlist). For Plan 03's tests, the snapshot fixtures land in Plan 05 — for this plan's tests, assertions inspect the value structurally (length 64, hex) without surfacing it through `t.assert.snapshot`. |
| T-02-03-07 | T (tampering) | ND1 default-index-set check | mitigate | Pre-flight reads current.default at build time. Graylog server-side also refuses with BadRequestException on the default. Two layers — wrapper-side check + server-side check — and the wrapper-side check surfaces the refusal as a structured dry-run error BEFORE the agent commits. |
</threat_model>
