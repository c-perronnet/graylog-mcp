RESEARCH.md §Set Default Pre-flight Algorithm (UPDATED D-13 + m2):
- GET /api/system/indices/index_sets/{id} returns IndexSetResponse with field can_be_default: boolean (the server's derived eligibility flag — absorbs the regular: true invariant today AND any future eligibility rules)
- can_be_default === false means the index set is events-style OR system-template OR otherwise not eligible. Graylog server-side throws 409 if you try to PUT /default on such a set.
- Pre-flight reads current.can_be_default; if false, throw a GraylogValidationError (Phase 0 — already shipped) with reason default_eligibility_failed, message naming current.title + current.id + can_be_default:false.

RESEARCH.md §Cycle Deflector Behavior (UPDATED D-14):
- POST /api/system/deflector/{indexSetId}/cycle returns 204 (void on the Java side). The cycle is SYNCHRONOUS — DeflectorResource.cycle calls indexSet.cycle() directly, NOT via systemJobManager.submit. No system_job_id returned.
- Side effect: closed-index range rebuild kicks off as a separate system job — observable via GET /system/jobs but not strictly necessary for routing new messages (only for searching the just-closed index).
- D-14 UPDATED envelope (CONTEXT.md 2026-05-15 revision): { rotated: true, message: "Cycled index set <id>; closed previous active index", side_effects: { observable_at: "/system/jobs", describes: "Graylog spawns an IndexRangesUpdateJob to rebuild the closed index's ranges; the rotation itself is complete on response." } }
- This is NOT the D-15 async envelope.

RESEARCH.md §Pitfall ND3:
- DeflectorResource.checkCycle throws 400 if !indexSet.getConfig().isWritable(). Pre-flight inside cycle_deflector.build() — GET current, check current.writable === false, surface structured pre-flight error if so.
