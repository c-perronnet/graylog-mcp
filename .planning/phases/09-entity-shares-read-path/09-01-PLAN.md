<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP agent → tool handler | Agent-supplied `entityGrn` / `entityType` / `entityId` cross into the handler — untrusted input that becomes a request path. |
| Tool handler → Graylog REST API | The handler constructs a URL path and POSTs to live Graylog 7.0.6; Graylog enforces authorization server-side. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | request path built from agent-supplied GRN/id (`prepare-share.js`, both handlers) | mitigate | `parseGrn`/`buildGrn` validate the 6-token structure + restricted type set client-side before any HTTP call; `encodeURIComponent` encodes the GRN so injected `:` or `/` cannot mis-route or path-traverse the JAX-RS router. Verified by Task 1 test case 1 (path contains `%3A`, no raw `:`) and case 5 (malformed GRN → no HTTP call). |
| T-09-02 | Tampering / Elevation | regressing to the brief's wrong `PUT` path, or dropping `/prepare` to hit the mutating commit endpoint | mitigate | The path is hardcoded in `prepare-share.js` with the `/prepare` suffix and a `path.endsWith("/prepare")` self-guard; Task 3 acceptance gates `grep` for absence of `PUT` and presence of `/prepare`. Phase 9 never touches `POST .../entities/{grn}` (commit). |
| T-09-03 | Information Disclosure | logging full grant maps / GRNs at info level | mitigate | Grant detail stays inside the tool's JSON response only; no `console.error`/`console.log` of grant maps or GRNs is added. Failures map through `wrapGraylogError` (standard envelope, no grant dump). |
| T-09-04 | Spoofing | `_testConnection` seam reachable from a production agent payload | mitigate | The seam is deliberately absent from `GetEntitySharesSchema`/`ListGranteesSchema`; zod `strip` mode drops it from real-agent payloads; it is re-merged only from raw pre-zod args inside the handler (the verified `get-pipeline.js` pattern). |
| T-09-05 | Information Disclosure | over-trusting `active_shares` as the complete ACL | accept | `active_shares` excludes the calling user's own grant by Graylog design (`getForTargetExcludingGrantee`). Mitigated by documentation, not code: the `get_entity_shares` tool description states this explicitly (Task 4). No code defense possible — it is a server-side filter; an honest tool description is the control. |

No `high`-severity threats: Phase 9 ships only non-mutating reads against a `@NoAuditEvent` endpoint. The mutating-write threat surface (read-merge-write, drift, ownerless guard) is Phase 10.
</threat_model>
