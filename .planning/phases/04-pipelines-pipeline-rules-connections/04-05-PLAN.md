<objective>
Ship PIPE-13 (`connect_pipelines_to_stream`) and PIPE-14 (`disconnect_pipelines_from_stream`) — the two new requirements added to Phase 4 via CONTEXT.md D-01. Both endpoints share the same Graylog wire surface (`POST /api/system/pipelines/connections/to_stream`) but with REPLACE-the-full-set semantics. The wrapper does GET-merge-PUT (union for connect) and GET-subtract-PUT (difference for disconnect) client-side to make the agent-facing contract intuitive ("attach pipelines" / "detach pipelines") instead of "overwrite the entire set" — which is the highest-severity Phase 4 connection bug (Pitfall 2).

Purpose: Phase 4's dependency line on Phase 3 says "`connect_pipelines_to_stream` needs stream IDs" — these are the cross-phase glue that lets agents wire stream → pipeline routing end-to-end. Without the GET-merge-PUT wrapper, a single `connect_pipelines_to_stream({streamId: "s1", pipelineIds: ["new"]})` call would SILENTLY disconnect every previously-connected pipeline — a destructive-by-omission footgun (the agent's intent was "add `new`", not "make `new` the only pipeline").

Output: 2 new handler files + 2 new schemas + 2 register lines (barrel grows from 12 → 14, completing the Phase 4 tool surface) + 2 new tools.js entries + comprehensive tests including the Pitfall 2 acceptance gate (verify that adding ["new"] to a stream with existing ["a","b"] produces a POST body with `pipeline_ids: ["a","b","new"]`, NOT `pipeline_ids: ["new"]`).

    // PIPE-13 — connect_pipelines_to_stream. ATTACH semantics.
    //
    // POST /api/system/pipelines/connections/to_stream is REPLACE-the-full-set
    // (PipelineConnectionsResource.java:81-100 — connectionsService.save(connection)
    // is full replacement, NOT merge). To implement "attach pipelines" at the
    // agent boundary, the wrapper:
    //   1. GET /api/system/pipelines/connections/{streamId} → current set
    //      (404 → treat as empty set; the first POST creates the record)
    //   2. merged = union(current.pipeline_ids, args.pipelineIds)
    //   3. POST /api/system/pipelines/connections/to_stream with merged set
    //
    // Pitfall 2: forgetting the merge step silently disconnects previously-
    // connected pipelines from the stream. Test 2 (Pitfall 2 acceptance gate)
    // proves the merge fires by verifying body.pipeline_ids contains BOTH
    // current AND args.pipelineIds entries.
    //
    // Idempotency: pipelines already in the current set surface in
    // existingMatches with similarity_reason: "already_connected" — agent
    // sees the no-op attaches without having to diff.
    //
    // pipeline_ids are sorted on the wire for deterministic snapshot fixtures
    // (Graylog's wire type is Set<String> so order is not significant
    // server-side; sorting is purely a snapshot-stability concern).

    import { defineMutatingHandler } from "../_shared/handler.js";
    import { ConnectPipelinesToStreamSchema } from "./schemas.js";
    import { makeClient } from "../../graylog/client.js";

    export const handleConnectPipelinesToStream = defineMutatingHandler({
        name: "connect_pipelines_to_stream",
        schema: ConnectPipelinesToStreamSchema,
        async build(args) {
            const client = makeClient(args._conn);
            const getPath = `/api/system/pipelines/connections/${args.streamId}`;

            let current;
            try {
                current = await client.request("GET", getPath, null);
            } catch (err) {
                // 404 = no record yet; first POST creates it.
                if (err?.isGraylogError && err.status === 404) {
                    current = { stream_id: args.streamId, pipeline_ids: [] };
                } else {
                    throw err;   // 5xx / 403 / etc. propagate via wrapGraylogError
                }
            }

            const currentArray = Array.isArray(current?.pipeline_ids) ? current.pipeline_ids : [];
            const currentSet = new Set(currentArray);

            // Pitfall 2 ACCEPTANCE GATE — the load-bearing line of this handler.
            // GET-merge-PUT preserves previously-connected pipelines.
            const existingMatches = [];
            for (const id of args.pipelineIds) {
                if (currentSet.has(id)) {
                    existingMatches.push({ id, similarity_reason: "already_connected" });
                }
                currentSet.add(id);
            }
            const merged = [...currentSet].sort();

            return {
                method: "POST",
                path: "/api/system/pipelines/connections/to_stream",
                body: { stream_id: args.streamId, pipeline_ids: merged },
                existingMatches,
                postApplyEstimate: { stream_id: args.streamId, pipeline_ids: merged },
            };
        },
        apply: (client, req) => client.request(req.method, req.path, req.body),
        summarize: (args) =>
            `Connect ${args.pipelineIds.length} pipeline(s) to stream ${args.streamId}`,
    });
    ```

    // PIPE-14 — disconnect_pipelines_from_stream. DETACH semantics.
    //
    // Same wire endpoint as PIPE-13 (POST /to_stream — REPLACE-the-full-set
    // server-side); the wrapper does GET-subtract-PUT to preserve the
    // remaining connections (Pitfall 2 mirror — detaching pipeline X
    // should not silently disconnect Y and Z).
    //
    // 404 on the GET means there's no connection record yet → currentSet is
    // empty → reduced is empty → POST still fires with pipeline_ids: []
    // (idempotent no-op).
    //
    // Idempotency: pipelines that were already NOT connected surface in
    // existingMatches with similarity_reason: "not_currently_connected".

    import { defineMutatingHandler } from "../_shared/handler.js";
    import { DisconnectPipelinesFromStreamSchema } from "./schemas.js";
    import { makeClient } from "../../graylog/client.js";

    export const handleDisconnectPipelinesFromStream = defineMutatingHandler({
        name: "disconnect_pipelines_from_stream",
        schema: DisconnectPipelinesFromStreamSchema,
        async build(args) {
            const client = makeClient(args._conn);
            const getPath = `/api/system/pipelines/connections/${args.streamId}`;

            let current;
            try {
                current = await client.request("GET", getPath, null);
            } catch (err) {
                if (err?.isGraylogError && err.status === 404) {
                    current = { stream_id: args.streamId, pipeline_ids: [] };
                } else {
                    throw err;
                }
            }

            const currentArray = Array.isArray(current?.pipeline_ids) ? current.pipeline_ids : [];
            const currentSet = new Set(currentArray);

            const existingMatches = [];
            for (const id of args.pipelineIds) {
                if (!currentSet.has(id)) {
                    existingMatches.push({ id, similarity_reason: "not_currently_connected" });
                } else {
                    currentSet.delete(id);
                }
            }
            const reduced = [...currentSet].sort();

            return {
                method: "POST",
                path: "/api/system/pipelines/connections/to_stream",
                body: { stream_id: args.streamId, pipeline_ids: reduced },
                existingMatches,
                postApplyEstimate: { stream_id: args.streamId, pipeline_ids: reduced },
            };
        },
        apply: (client, req) => client.request(req.method, req.path, req.body),
        summarize: (args) =>
            `Disconnect ${args.pipelineIds.length} pipeline(s) from stream ${args.streamId}`,
    });
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → MCP wrapper | Agent supplies streamId + pipelineIds; both crossed via zod schema |
| MCP wrapper → Graylog GET | Pre-flight reads current pipeline_ids set; 404 is the "no record" signal |
| MCP wrapper → Graylog POST | Merged/reduced set replaces server-side set; the wrapper's correctness is the only thing standing between the agent's "attach" intent and an accidental "replace-all" |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05-01 | T (Tampering) | Pitfall 2 — naive replacement silently disconnects existing | mitigate | Both handlers do GET-merge-PUT / GET-subtract-PUT; tests pin body.pipeline_ids contains BOTH currentSet AND args.pipelineIds for connect (or currentSet \ args.pipelineIds for disconnect) |
| T-04-05-02 | I (Information Disclosure) | leak of foreign streamId's connections via stale cache | accept | No connection cache in this plan (no per-connection-state cache exists for connections); each call does a fresh GET. Per-request shape isolates streams |
| T-04-05-03 | E (Elevation of Privilege) | apply runs against stale current set (race with concurrent agent attach) | accept | Network-layer race; not a structural threat surface. The wrapper's GET-then-POST is atomic from the wrapper's perspective. A concurrent agent attaching at the same moment would interleave reads; the LATER POST wins. Documented as a known race — agents serialize connection mutations or accept last-write-wins |
| T-04-05-04 | D (Denial of Service) | unbounded pipelineIds array | mitigate | zod schema enforces .min(1); no upper bound, but Graylog's wire request limit (~8MB) bounds it implicitly. No catastrophic-backtracking surface |
| T-04-05-05 | S (Spoofing) | 404-treated-as-empty masks an authorization failure | accept | Graylog's 404 here means "no PipelineConnections record exists" (verified RESEARCH Assumption A7). 403 would surface as GraylogPermissionError and propagate; 404 is a separate code path |
